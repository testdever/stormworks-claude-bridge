# stormworks-claude-bridge

Claude に Stormworks の計測実験を任せるための仕組み。企画書は `docs/brief.md`、決めたことは `docs/decisions/`、試作で確かめることは `docs/verification.md`。

## ファイルの置き場所（リポジトリ → 本人の PC）

| リポジトリのファイル | PC での置き場所 | 使うとき |
|---|---|---|
| `relay/relay.py` | デスクトップの `relay.py`（どこでもよい。そこで `python relay.py …` を実行する） | いつも |
| `game/addon/server/ClaudeBridge/script.lua` | `Steam\steamapps\common\Stormworks\rom\data\missions\ClaudeBridge\script.lua` | 専用サーバー |
| `game/addon/server/ClaudeBridge/playlist.xml` | `Steam\steamapps\common\Stormworks\rom\data\missions\ClaudeBridge\playlist.xml` | 専用サーバー |
| `game/addon/ClaudeBridge/script.lua` | `%APPDATA%\Stormworks\data\missions\ClaudeBridge\script.lua` | 1人用のゲーム本体 |
| `game/addon/ClaudeBridge/playlist.xml` | `%APPDATA%\Stormworks\data\missions\ClaudeBridge\playlist.xml` | 1人用のゲーム本体 |
| `game/q2_values_and_commands.lua` | 試験用の機体のマイコンの Lua ブロック（貼り付け） | 機体を作るとき |
| `experiments/*.json` | `relay.py` と同じフォルダの `experiments\` の下 | 手順書を流すとき |

アドオンの `script.lua` を貼り替えたら、ワールドを作り直す（専用サーバーは `%APPDATA%\Stormworks\saves\autosave_server` を消す）。
Claude は変更のたびに、どのファイルを変えたかと、新しく増えたファイルを伝える。

## 試作 Q1：マイコンから値が届くか

機体のマイコンから、同じPCの中継プログラムへ、物理センサーの値が1秒に10回以上・60秒間・欠けずに届くかを確かめる。

### 用意するもの

- メインPCに Python 3.10 以上（`python --version` で確かめる）
- このリポジトリ（`git clone` するか、GitHub の「Code → Download ZIP」）

### 手順

1. このリポジトリのフォルダで、中継プログラムを起動する。

   ```
   python relay/relay.py
   ```

   「待ち受け中」と出たら、そのままにしておく。最初に値が届いてから60秒たつと、自動で止まって結果を出す。

2. Stormworks を起動し、1人用のワールドに入る。

3. 試験用の機体を作る。
   - 物理センサー（Physics Sensor）を1つ置く。
   - マイコンを1つ置き、中にコンポジットの入力ノードを1つと Lua ブロックを1つ作る。
     入力ノード → Lua ブロックのコンポジット入力、とつなぐ。
   - Lua ブロックに `game/q1_send_values.lua` の中身を貼る。
   - 物理センサーのコンポジット出力を、マイコンの入力ノードにつなぐ。
   - （任意）Lua ブロックの出力1〜3に、送った回数・正常な返事の数・エラーの返事の数が出る。
     画面に出したいときは、数値の出力ノードとダイヤルなどにつなぐ。

4. 機体を出す。動かさなくてよい（値が届くかを見るだけなので、止まっていても構わない）。

5. 中継プログラムの画面で「受信」が増えていくことを確かめる。60秒たつと止まり、「---- 結果 ----」が出る。

6. 「---- 結果 ----」から下を、Claude に貼って伝える。
   記録は `logs/` にできる（`q1-日時.jsonl` が全部の値、`q1-日時-summary.json` がまとめ）。
   全部の値のファイルも送ってもらえれば、物理センサーの出力の順番も読み取れる。

### 受信が始まらないとき

- 中継プログラムが動いているか（ウィンドウを閉じていないか）。
- マイコンの出力3（エラーの返事の数）が増えていないか。増えていれば、ゲームから中継プログラムにつながっていない。
- 別のプログラムがポート 8765 を使っていれば、`python relay/relay.py --port 8766` で起動し、Lua の `PORT=8765` も同じ番号に変える。

## 試作 Q2：中継プログラムからの指示で機体を動かせるか

中継プログラムが出した指示（出力1の値）が、2秒以内に機体に反映されるかを10回確かめる。

### 手順

1. 中継プログラムを Q2 の形で起動する。機体より先に起動しておく。

   ```
   python relay/relay.py --mode q2
   ```

   機体を先に出していると、その間に送られた要求がゲームの中に溜まり、最初の数秒は返事が遅れる。
   結果の「送り直した回数」が 0 でなければ、これが起きている。

2. Q1 の機体のマイコンの Lua を、`game/q2_values_and_commands.lua` の中身に貼り替える。
   配線は Q1 と同じ（物理センサー → 入力ノード → Lua ブロック）。
   - Lua ブロックの出力1〜8 に、指示の値が出る。今回使うのは出力1だけ。
   - 送った回数・正常な返事の数・エラーの返事の数は、出力30〜32 に移った。出力29 は、古い要求への返事を無視した数。
   - （任意）出力1を数値の出力ノードからランプやモーターなどにつなぐと、指示で 1 と 0 が切り替わるのが目で見える。
     機体を回しているモーターにつなげば、回転が変わる様子も記録に残る。

3. 機体を出す。値が届き始めて2秒後から、3秒ごとに出力1へ 1 → 0 → 1 … と指示が10回出る。
   全部反映されるか、最後の指示から5秒たつと自動で止まり、「---- 指示の結果 ----」が出る（30〜40秒ほど）。

4. 「---- 指示の結果 ----」から下と、`logs/` の `q2-日時.jsonl` と `q2-日時-summary.json` を Claude に送る。

「反映」は、マイコンが指示を受け取って出力に出し、次の送信で「反映した」と知らせてきたときとする。
中継プログラムは、指示を出してからその知らせが届くまでの時間を測る。

## 試作 Q3：アドオンから機体を置いたり片付けたりできるか

中継プログラムの指示で、アドオンが機体を置く・片付けるを10回くり返し、すべてできるかを確かめる。

### 最初に一度だけやること

1. **試験用の機体を保存する。** Q2 の機体（物理センサーと、`game/q2_values_and_commands.lua` を貼ったマイコンを載せたもの）を、
   ワークベンチで名前を付けて保存する。名前は何でもよいが、`|` は使わない（例：`claude_test`）。
2. **アドオンのフォルダを置く。** このリポジトリの `game/addon/ClaudeBridge` フォルダを、フォルダごと
   `%APPDATA%\Stormworks\data\missions\` の下にコピーする。
   `%APPDATA%\Stormworks\data\missions\ClaudeBridge\playlist.xml` と `script.lua` ができていればよい。
3. **Stormworks を起動し直す**（起動中にフォルダを置いた場合。アドオンの一覧に確実に出すため）。
4. **新しいワールドを作る。** ニューゲームの画面で「Enabled Addons」を開き、手元の（ワークショップではない）一覧から
   「Claude Bridge」を有効にして、ワールドを作る。ほかの設定は何でもよい。

### 手順

1. 中継プログラムを Q3 の形で起動する。`claude_test` は手順1で付けた名前に替える。

   ```
   python relay/relay.py --mode q3 --vehicle claude_test
   ```

2. 作ったワールドに入り、まわりが開けた場所に立つ。機体は、プレイヤーの位置から Z の方向に 15 m、3 m 上に出る。
   ぶつかりそうなら、`--offset 0,3,30` のように、ずらす量（x,y,z、m）を変えて起動し直す。
3. アドオンから連絡が来ると自動で始まる。機体を置く → 3秒待つ → 片付ける → 2秒待つ、を10回（1分ほど）。
   ゲームのチャットにも「[Claude] spawned …」「[Claude] despawned …」と出る。
4. 「---- 機体を置く・片付けるの結果 ----」から下と、`logs/` の `q3-日時.jsonl` と `q3-日時-summary.json` を Claude に送る。

置いた機体のマイコンからも値が届くので、結果の「マイコンからの値」が 0 件でなければ、機体が実際に出て動いていたと分かる。
チャットに「spawn failed」と出たら、機体の名前が保存名と合っていない。

## 試作 Q4・Q5：誰も接続していない専用サーバーで物理が進むか、メインPCが重くならないか

メインPCの裏で専用サーバーを動かし、ゲームからは接続しない状態で、置いた機体の物理が60秒間進み続けるかを確かめる（Q4）。
キープアクティブブロックを積んだ機体と積んでいない機体を1台ずつ試し、どちらで進むかも分かるようにする。
同時に、専用サーバーの CPU とメモリを記録し、その間にメインPCで作業して重く感じるかを確かめる（Q5）。

### 最初に一度だけやること

1. **専用サーバーはゲーム本体に入っている**ので、別に入れなくてよい。
   `server64.exe` は Stormworks（ゲーム本体）のフォルダにある（例：`Steam\steamapps\common\Stormworks\server64.exe`）。
   フォルダは、Steam のライブラリで Stormworks を右クリック →「管理」→「ローカルファイルを閲覧」で開ける。
2. **キープアクティブブロックを積んだ機体を用意する。** Q3 で保存した `claude_test` に、キープアクティブブロックを本体に1つ足して、
   `claude_test_ka` の名前で別に保存する。（`claude_test` はそのまま残す）
3. **専用サーバーを一度起動して閉じる。** 手順1のフォルダの `server64.exe` を起動し、ワールドの読み込みが終わったら、
   黒い窓を閉じて止める。これで `%APPDATA%\Stormworks\server_config.xml` ができる。
4. **アドオンを置く。** 専用サーバーは、Q3 でゲーム用に置いた `%APPDATA%\Stormworks\data\missions\ClaudeBridge` をそのまま使う。
   中の `playlist.xml` が、このリポジトリの最新の `game/addon/ClaudeBridge/playlist.xml`（1行目に `path_id` があるもの）になっているか確かめる。
5. **専用サーバーの設定を書き換える。** 専用サーバーを止めた状態で、`%APPDATA%\Stormworks\server_config.xml` を、
   念のため別の名前でコピーして控えを取ってから、メモ帳で開く。`<playlists>` の部分を次のようにして保存する。
   ほかのアドオン（標準のミッションなど）を外して、軽くするため。
   `<playlists/>` のように1つのタグになっていたら、それを丸ごと置き換える。

   ```
   <playlists>
   	<path path="app_data/data/missions/ClaudeBridge"/>
   </playlists>
   ```

   サーバーは、受け付けないアドオンの行を消して保存し直す。起動して閉じたあとにこの行が残っていれば、受け付けられている。
   （`rom/data/missions/ClaudeBridge` や `ClaudeBridge` の書き方、ゲーム本体のフォルダに置く形では、行が消されて読み込まれなかった）
   受け付けられた設定の例は `docs/examples/server_config.xml`。
6. **専用サーバーのワールドを作り直す。** アドオンはワールドを作るときに決まり、あとから足せない。
   `%APPDATA%\Stormworks\saves\autosave_server` があれば、名前を変えて（例：`autosave_server_old`）よけておく。
   次に `server64.exe` を起動したとき、ClaudeBridge 入りの新しいワールドが作られる。

### 手順

1. Stormworks（ゲーム本体）は閉じておく。専用サーバーだけの負荷を測るため。
2. 中継プログラムを Q4 の形で起動する。

   ```
   python relay/relay.py --mode q4
   ```

3. ゲーム本体のフォルダの `server64.exe` を起動する。ワールドが読み込まれ、アドオンから連絡が来ると自動で始まる。
   `claude_test` を60秒、`claude_test_ka` を60秒、順に置いて回しながら様子を見る（全部で2分半ほど）。
   **終わるまで、ゲームから専用サーバーに接続しない。**
4. その間、メインPCでふだんの作業（ブラウザ、動画など）をして、重く感じたかを覚えておく。
5. 「---- 誰も接続していない専用サーバーで物理が進むかの結果 ----」から下と、`logs/` の `q4-日時.jsonl` と
   `q4-日時-summary.json`、それに**重く感じたかどうか**を Claude に送る。終わったら専用サーバーの黒い窓を閉じる。

### うまくいかないとき

- **中継プログラムが「アドオンからの連絡」を待ったまま始まらない：** アドオンが読み込まれていない。
  専用サーバーを止めて `server_config.xml` を開き、`<playlists>` の中の行が消えていないか見る。
  消えていたら、置き場所（手順4）と名前を確かめ、手順5・6をやり直す。
- **アドオンが動いているかを外から見る：** アドオンは Windows のデバッグ出力に、動いている様子を書き出す。
  Microsoft の無料の道具 DebugView（https://learn.microsoft.com/sysinternals/downloads/debugview ）で見られる。
  1. DebugView を入れて `Dbgview64.exe` を起動する（「Capture」メニューの「Capture Win32」に印が付いていること）。
     「Edit」→「Filter/Highlight」の Include に `*ClaudeBridge*` と入れると、関係する行だけになる。
  2. 中継プログラムと `server64.exe` を起動して、30秒ほど様子を見る。
  3. 見え方で、どこで止まっているかが分かる。
     - 何も出ない：アドオンが読み込まれていないか、スクリプトが動いていない。
     - `onCreate` だけ出て `tick=` が出ない：誰も接続していないと、アドオンの毎 tick の処理が呼ばれない。
     - `tick=` は出るが `replies=0` のまま：アドオンは要求を出しているが、返事が来ない（専用サーバーの通信が届いていない）。
     - `reply 1: connect…` のような行：中継プログラムにつながっていない（ポートの違いなど）。
- **「置く → できなかった」：** 専用サーバーから機体の保存が見えていない。
  `%APPDATA%\Stormworks\data\vehicles\` に `claude_test.xml` と `claude_test_ka.xml` があるか確かめて、Claude に伝える。
- **機体を置く場所：** 既定は Q1 で機体があった場所の 3m 上（ワールドの座標 -260.9, 8, -18949）。
  水に落ちるなど不都合があれば、`--pos x,y,z` で変える。

## 試作 Q6・Q7・Q9：手順書を流す、異常で止まる、ゲームを裏で動かしても邪魔にならない

Claude が書いた手順書（`experiments/*.json`）を中継プログラムが最後まで流す。見張りは、マイコンからの値が途切れた・
アドオンからの連絡が途切れた・機体が消えた・値が壊れた（数でない値）を見つけたら、実験を止めて理由を残し、機体を片付ける。
手順書の `watch.stop_if` で「この出力がこの範囲を外れたら止める」も書ける。

### 用意（一度だけ）

1. `relay/relay.py` と `game/addon/ClaudeBridge/script.lua` を、それぞれの置き場所（上の表）に貼り替える。
   `experiments` フォルダの4つの手順書を、`relay.py` と同じフォルダの `experiments\` に置く。
2. ゲームで `claude_test` をワークベンチに出し、マイコンの Lua ブロックを `game/q2_values_and_commands.lua` の新しい中身に貼り替えて、
   同じ名前（`claude_test`）で上書き保存する（試験用に壊れた値を送る機能と、返事がない間は送り直しの間隔を伸ばす作りが増えた）。
3. **ウィンドウ表示**の Stormworks で、「Claude Bridge」だけを有効にした新しい1人用ワールドを作って入る。最初の島は既定のまま。

### 手順

1. **Q6・Q9：** ゲームを裏にして（ほかのアプリを前にして）、次を実行する。終わるまで1分ほど。
   その間はゲームに触らず、ふだんの作業をする。

   ```
   python relay.py --run experiments\q6_physics_sensor_order.json
   ```

   プレイヤーが実験場所の近く（機体の 10m 手前）へ移り、Q1 で機体が地面に乗っていた場所（-260.9, 7, -18949）に機体が出て、
   モーターが回って止まり、片付けられる。機体が落ち続けたら（置いた場所に足場がない）、見張りが止める。
   **作業中に、マウスやキーボードを取られたか、ゲームのウィンドウが前に出てきたか、音が気になったか**を覚えておく（Q9）。
2. **Q7：** 次の3つを順に実行する。どれも途中で止まるはず。
   - `python relay.py --run experiments\q7_vanish.json`（アドオンが機体を消す）
   - `python relay.py --run experiments\q7_nan.json`（マイコンが壊れた値を送る）
   - `python relay.py --run experiments\q7_pause.json`（「ここでゲームを一時停止する（Esc）」と出たら、ゲームを Esc で一時停止する。
     止まったと出たら、一時停止を解く）
3. それぞれの「---- 手順書「…」の結果 ----」から下と、`logs/` の `run-日時.jsonl`・`run-日時-summary.json`・`run-日時-addon.jsonl`、
   Q9 の感じ方を Claude に送る。

ゲームが裏にあると止まってしまう（ゲームがウィンドウの外では一時停止する）場合は、Q6 が「アドオンからの連絡が途切れた」で止まる。それも大事な結果なので、そのまま送る。

## テスト

```
python -m unittest discover -s relay/tests
```

マイコンの Lua をゲームの代わりの環境で試すテストは、`pip install lupa` を入れたときだけ動く。
Windows のスマート アプリ コントロールが lupa の一部（Lua 5.3・5.4）を止めることがあるので、テストは動く版（5.1 など）を自動で選ぶ（`relay/tests/luart.py`）。

## 返事がないときの送り直し

アドオンとマイコンは、中継プログラムから返事がない（止まっている）間、送り直しの間隔を 1秒 → 2秒 → 4秒 … と伸ばし、最長10秒にする。
返事が来たら、すぐ元の速さに戻る。間隔を伸ばさないと、ゲームの中に要求が溜まり、ワールドを抜けるときにゲームが落ちる見込みが高い
（`docs/notes/experiment-runs.md`）。古い Lua の機体やワールドを使うときは、ゲームを終了する前に `python relay/relay.py --seconds 0` を動かしておく。

## 実験の途中で止まったとき（Esc・ゲームが落ちた）

- **Esc で一時停止した・ゲームが落ちた：** アドオンからの連絡が3秒途切れると、見張りが理由を残して止める。記録とまとめはそこまでの分が残る。
- **残った機体：** アドオンは、置いた機体をワールドの保存データ（`g_savedata`）に覚えておき、ワールドを読み込んだときに片付ける
  （チャットに「[Claude] despawning leftover vehicle …」）。一時停止を解いたあと、中継プログラムから30秒返事がなければ、そのときも片付ける
  （「[Claude] no reply from relay, despawning …」）。
- **残った機体の値が混ざった：** 2台以上のマイコンから同時に値が届くと、見張りが「2台以上のマイコンから値が届いている」で止める。
- **途中で止めたいとき：** ゲームのチャットに `?claude stop` と打つ。アドオンがすぐ機体と標的を片付け、中継プログラムは「本人がチャットで止めた」で止める。
  中継プログラムの記録は1行ずつすぐ書き出すので、中継プログラムを途中で閉じても、そこまでの記録は残る。

## FCS の試験の下調べ：標的に当たったことを数えられるか

射撃管制マイコン（FCS）の試験を自動にするための下調べ。アドオンが標的を置き、当たったことをゲームの知らせ（`onVehicleDamaged`）で数える。
標的の座標は、中継プログラムが FCS に直接渡す（キーパッドで入れなくてよい）。

### 用意（一度だけ）

1. **標的を作る：** 一辺 4 m くらいの、水に浮く標的を作り、`claude_target` の名前で保存する。マイコンなどは要らない。
2. **test calc につなぎのマイコンを付ける：** 試験 E3 で使っていたマイコン（FCS のデバッグ出力と、砲身の Tilt・俯仰ピボットの角度を受けるもの）の
   Lua を `game/q2_values_and_commands.lua` に貼り替える。そのマイコンにコンポジットの出力ノードを足し、Lua のコンポジット出力をつなぐ。
   その出力を、FCS の目標の入力（IN2。今キーパッドの値が入っているところ）につなぎ替えて、上書き保存する。
   - つなぎの Lua の出力 1 = X、2 = Z、3 = Y（高さ）、4 = 1 が出る（test calc の FCS は IN2 を ch1 = X、ch2 = Z、ch3 = Y で読み、X が 0 でなければ目標有効とする）。
     並びは手順書の aim_target の channels（[X, Y, Z, 有効] の順にチャンネルを書く）で変えられる。
   - つなぎの Lua は、入力の数値 32ch とオン/オフ 32ch を毎回中継プログラムに送る（撃った瞬間の照準のずれを、あとで記録から計算する）。
3. 新しいアドオン（`game/addon/ClaudeBridge/script.lua`）を置き、「Claude Bridge」を有効にした新しいワールドを作る。
   **ワールドの設定で、機体が壊れる（vehicle damage）をオンにしておく。** オフだと当たっても知らせが来ない見込み。

### 手順

1. `test calc` を陸に固定して出し、そのそばに立って、撃ちたい海の方向を向く。中継プログラムを起動する（デスクトップの relay フォルダで）。

   ```
   python stormworks-claude-bridge/relay/relay.py --run stormworks-claude-bridge/experiments/fcs_probe_target.json
   ```

2. 10 秒後、向いている方向の 2 km 先に標的が出て、チャットに座標が出る（「[Claude] target claude_target id=… at X=… Y=… Z=…」）。
   同じ座標が FCS に渡るので、射撃許可を入れて撃つ。当たると、チャットに「[Claude] target damaged x…」と出る。
3. 5 分たつと標的が片付けられ（FCS の目標は無効になる）、結果に「機体 … が傷ついた知らせ」の件数が出る。
   この手順書は手で操作するので、一時停止しても 10 分までは止まらない。

## FCS V-07（手放し）：1 km・2 km で 10 発ずつ

射撃許可と撃つ数も中継プログラムが決める。test calc も手順書が出して片付ける。本人は、新しいワールドで陸に立ち、撃ちたい海の方向を向くだけ。
1発ごとに、置いた場所に新しい標的を出し直してから撃つ（標的が回ると当たる面の広さが変わる。当たった標的は位置と向きを戻しても回り続ける）。
標的は海面の高さに置き、標的の位置が 1 秒の間 0.3 m 以内に収まってから射撃許可を出す（高いところから落とすと上下に揺れ、FCS がそれを追って外れた）。

つなぎの Lua を変えたら、エディターで貼る代わりに、保存済みの機体のファイルへ直接書く（前のファイルは `backup\vehicles` に残る）。

```
python stormworks-claude-bridge/tools/put_lua.py "test calc" stormworks-claude-bridge/game/fcs_bridge.lua --marker "-- FCS bridge:"
```

### 用意（一度だけ）

1. **つなぎの Lua を FCS 専用に替える：** test calc のつなぎのマイコン（4段の塔の下から3個目）の Lua を、`game/fcs_bridge.lua` に貼り替える。
   - 送るのは要るチャンネルだけ（デバッグの ch7 飛ぶ時間・ch8 距離・ch9 仰角の解・ch13 予測のずれ、ch20 砲身の Tilt、ch21 俯仰ピボットの角度）を、1秒に6回ほど。
   - 撃った瞬間は、マイコンの中で毎 tick 見て見つけ（試験 E3 と同じ：射撃可のあと砲身が 0.15°以上いっぺんに動いた）、1発ごとの記録を送る。
   - 出力の数値 1〜8 は中継プログラムの指示（ch1 = X、ch2 = Z、ch3 = Y）。on/off 出力 1 が射撃許可（指示 5）。中継プログラムから2秒返事がなければ、自分で射撃許可を切る。
2. **射撃許可の線：** つなぎのマイコンの中に Composite Read（on/off、チャンネル 1）を置いて Lua のコンポジット出力につなぎ、on/off の出力ノードに出す。
   その出力を FCS 本体の「allow fire」につなぐ（操縦席のスイッチからの線は外す）。test calc を上書き保存する。
3. 新しいアドオンを置き、「Claude Bridge」を有効にした新しいワールドを作る（vehicle damage をオン、電気は無限）。

### 手順

1. 陸に立って、撃ちたい海の方向を向く。手で test calc を出さない（2台から値が届いて止まる）。中継プログラムを起動する（デスクトップの relay フォルダで）。
   test calc は、向いている方向の右 10 m・後ろ 5 m に出る。

   ```
   python stormworks-claude-bridge/relay/relay.py --run stormworks-claude-bridge/experiments/fcs_v07_auto.json
   ```

2. 約 16 秒後に 1 km 先に標的が出て、10 発撃つ。続けて同じ方向の 2 km 先に標的が出て、10 発撃つ（全部で3〜4分）。その間はゲームを裏にして、ほかの作業をしていてよい。
3. 結果に、距離ごとの「何発中何発当たり」と「撃った瞬間の照準のずれ（偏り・ばらつき、m）」、標的の向きの変わり方が出る。
   途中で止めたいときは、チャットに `?claude stop`。
